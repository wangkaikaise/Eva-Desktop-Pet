# 伊娃桌面宠物 Windows 版开发规格

版本基准：Mac 2.0.3 / Windows 13.3.1
目标平台：Windows 10 22H2、Windows 11，x64 与 arm64
产品名：中文“伊娃桌面宠物”，英文“Eva Desktop Pet”

## 1. 产品目标

伊娃不是系统监控悬浮窗加机器人皮肤，而是一位安静、温暖、有反应但不过度打扰的桌面伙伴。所有功能必须围绕三个核心价值：陪伴感、可玩性、低打扰。

设计优先级：

1. 角色造型和动作连续一致。
2. 拖动、点击和状态切换必须立即响应。
3. 长时间陪伴时安静、柔和、低资源占用。
4. 性能数据、提醒和设置服务于角色，不抢夺视觉中心。

## 2. 不可偏离的视觉真值

以 `assets/reference/eva-final-desktop-reference.png` 为唯一最终效果参考。

角色要求：

- 小巧悬浮机器人，头部略大于躯干宽度。
- 白色圆润外壳、黑色横向面屏、低饱和蓝色眼睛。
- 胸前只能有一个圆形发光核心，必须位于躯干中轴。
- 不允许出现三个胸灯、六个光点、偏心胸灯、耳朵金属件、脖颈金属件或实体底座。
- 底部是透明悬浮光，不是圆盘、支架或机械底座。
- 常规动作共用同一角色骨架，不允许开心、休眠等状态突然换成另一套造型。
- 主体最多三种识别色：白色、黑色、低饱和蓝色。情绪色只能作为小面积柔光。

三种核心材质：

- 白色外壳：柔和高光、轻微灰色边缘、无金属脏污。
- 黑色面屏：接近黑色的玻璃面板，有轻微反射，不使用纯平灰块。
- 蓝色光：低饱和、边缘柔化、有光晕但不刺眼。

## 3. 分层渲染逻辑

Windows 版必须采用分层渲染，不要为每种状态替换整张角色图。

从后到前的推荐层级：

1. 防护罩层。
2. 拖动尾迹或巡航尾迹。
3. 底部透明光池。
4. 角色白色身体基底。
5. 黑色面屏覆盖层。
6. 动态眼睛层。
7. 单个胸部核心层。
8. 休眠、气泡和提示层。
9. 性能卡片层。

`eva-character-source-transparent.png` 是高分辨率透明角色来源。它仍包含源图眼睛，因此 Windows 运行时必须在其上绘制不透明黑色面屏覆盖层，再绘制当前动作眼睛。最终比例和位置以桌面参考截图为准。

## 4. 窗口与桌面行为

主窗口：

- 无边框、背景透明、不显示任务栏按钮。
- 默认尺寸为 220 × 220 逻辑像素的角色区域；为性能卡片和提示预留额外透明画布。
- 默认位于主显示器可用工作区右下角，距离右边 24 px、底部 42 px。
- 支持始终置顶开关。
- 支持多显示器和 Per-Monitor DPI Awareness V2。
- 拖动不能使用“窗口自动移动”和角色内部拖动两套机制同时工作。
- 鼠标按下后捕获指针，记录窗口起点和屏幕鼠标起点；每帧通过 `SetWindowPos` 直接设置 `origin + delta`，不对窗口位置做追赶插值。
- 可见角色和火箭区域必须有稳定命中层；透明窗口不能让鼠标事件穿透。
- 非交互光效、尾迹、性能卡片必须禁止命中测试。

Windows 窗口建议：

- 商用品质推荐：WinUI 3 + Win32 HWND + Windows Composition/Win2D。
- 使用 `WS_EX_TOOLWINDOW` 隐藏任务栏入口，按设置控制 TopMost。
- 透明合成优先使用 DirectComposition；不要依赖会强制软件渲染的整窗 WPF `AllowsTransparency=True` 作为最终方案。
- MVP 可先用 WPF 验证状态机，但发布前必须测量实际 CPU/GPU 和拖动帧率。

## 5. 动作状态机

状态枚举：`Idle`、`Hover`、`Cheer`、`Play`、`Sleep`。

通用规则：

- 状态切换使用 1.8 秒 ease-in-out 视觉过渡。
- 点击从“除当前状态外”的四个状态中随机选择，不能固定进入玩耍。
- 点击状态保持 12 秒；休眠保持 16 秒；到期后仅在状态未被用户再次改变时回到待机。
- 提示气泡显示约 8 秒，淡入 0.65 秒，淡出 0.55 秒。
- 拖动优先级高于普通动作；松手后身体使用约 0.48 秒弹性恢复，方向尾迹延迟约 0.52 秒后用 0.3 秒淡出。
- 动作速度设置范围 0.4–1.0，默认 0.8。

### 5.1 待机 Idle

- 横向位移：`sin(t × 0.13) × 4 px`。
- 纵向呼吸：`sin(t × 0.20) × 8 px`。
- 旋转：`sin(t × 0.11) × 2.2°`。
- 缩放：`1 + sin(t × 0.16) × 0.018`。
- 眼睛：轻微上弧、线宽约 3 px。
- 语义：安静陪伴，不应像巡航。

### 5.2 巡航 Hover

- 横向位移：`sin(t × 0.16) × 32 px`，必须明显大于待机。
- 纵向：`-12 + sin(t × 0.24) × 14 px`。
- 旋转：`cos(t × 0.16) × 6.5°`。
- 缩放：`1.025 + sin(t × 0.18) × 0.022`。
- 增加与移动方向相反的三条柔和尾迹。
- 眼睛：两条轻微向内倾斜的专注线。
- 语义：慢速飞行，不是原地上下浮动。

### 5.3 开心 Cheer

- 横向：`sin(t × 0.34) × 8 px`。
- 纵向：`-8 - abs(sin(t × 0.43)) × 19 px`。
- 旋转：`sin(t × 0.34) × 7°`。
- 缩放：`1.035 + abs(sin(t × 0.43)) × 0.032`。
- 眼睛：比待机更高的开心弧线，线宽约 3.3 px。
- 角色骨架、头身比例和胸部位置不得改变。

### 5.4 玩耍 Play

- 角色平滑变为白色小火箭，进入动画约 0.8 秒。
- 自动飞行轨迹为“8”字：横向 `sin(p) × 28% 容器宽`，纵向 `sin(2p) × 17% 容器高 - 6% 容器高`。
- 飞行方向根据轨迹切线计算，火箭头始终朝运动方向。
- 火箭颜色仍限制为白色机身、黑色舷窗、蓝色眼睛/推进光。
- 火箭状态必须可以拖动；拖动时停止自动轨迹，以鼠标方向决定 0°、90°、180°、-90° 朝向。
- 尾气和影子必须位于拖动方向反向，并随方向即时更新。
- 玩耍眼睛为两个带高光的圆眼；火箭舷窗中使用两条蓝色小胶囊眼睛。

### 5.5 休眠 Sleep

- 纵向：`9 + sin(t × 0.10) × 4 px`。
- 旋转：`-3 + sin(t × 0.08) × 1.2°`。
- 缩放：`0.97 + sin(t × 0.09) × 0.012`。
- 眼睛：低透明度闭眼弧线。
- 右上方显示玻璃胶囊样式的月亮与递增字号 `z z z`。
- 休眠提示要明显，但不能遮挡头部和拖动命中区。

## 6. 拖动动作

- 最小识别距离 1 px；方向判断需要累计/单步位移超过 4 px。
- 横向绝对位移大于纵向时判定 Left/Right，否则判定 Up/Down。
- 左右倾斜 ±8°，上移 -3°，下移 +3°。
- 拖动身体有轻微跃起：基础 y = -10 px，并附加最多 8 px 的节奏位移。
- 拖动时渲染三条方向尾迹；玩耍火箭渲染更长的尾气与柔光残影。
- 指针与窗口位置必须 1:1；角色内部动画可以有弹性，但窗口本身不能滞后。
- 在 100%、125%、150%、200% DPI 和跨屏拖动时都必须跟手。

## 7. 眼睛与胸部核心

眼睛必须与动作同步，使用 `assets/eyes/` 中的 SVG 作为形状参考：

- Idle：柔和浅弧。
- Hover：专注斜线。
- Cheer：更高、更开心的弧线。
- Play：圆形高光眼。
- Sleep：闭合低弧。

胸部核心：

- 永远只有一个，坐标锁定角色中轴 `x = 0`。
- Mac 标准归一化 y 偏移约为角色尺寸的 `+0.045`。
- 直径约为角色尺寸的 5.8%。
- 由白色中心、低饱和动作色环和柔光阴影组成。
- 状态色只改变小面积光色，不改变核心位置、数量或几何结构。
- 建议状态色：Idle `#70C2EB`、Hover `#85A8E8`、Cheer `#85DBB3`、Play `#57C7FA`、Sleep `#A89EDB`；实际显示需降低饱和并混入白光。

## 8. 情绪系统

情绪和动作是两个独立维度。动作控制身体表现；情绪控制提示语言和长期陪伴语气。

六种情绪：

- 开心营业 Cheerful
- 平静摸鱼 Calm
- 有点疲惫 Tired
- 工作烦躁 Frustrated
- 今日郁闷 Blue
- 专注奋斗 Focused

自动切换间隔：15、30、60 分钟，默认 30 分钟。默认情绪为 Calm，默认自动切换开启。

提示文案：

- Cheerful：“今天也很棒呀”“你的好心情，我收到啦”
- Calm：“慢一点也没关系”“陪你安静待一会儿”
- Tired：“累了就伸个懒腰吧”“先喝口水，再继续”
- Frustrated：“工作可以烦，别为难自己”“深呼吸，我陪着你”
- Blue：“今天不开心也没关系”“不用马上振作，我在这里”
- Focused：“专注模式，一起加油”“一步一步来就好”

## 9. 玻璃光效

### 9.1 底部光池

- 无实体底座。
- 宽约角色尺寸 72%，高约 46 px。
- 使用白色中心、低饱和蓝色中层和透明外缘的径向渐变。
- 模糊约 8 px，呼吸缩放幅度不超过 2%。
- 亮度设置 0.1–1.0，默认 0.72。

### 9.2 防护罩

三种样式：

- Halo：柔光圆环 + 旋转扫描弧 + 反向虚线刻度。
- Bubble：细玻璃圆边 + 点状内环 + 小段高光。
- Orbit：多段不同速度与方向的轨道弧。

规则：防护罩默认关闭；只使用透明线条和柔光，不填充大面积高饱和颜色；不可拦截鼠标。

## 10. 性能卡片

显示项：

- CPU 占用率，整数百分比。
- CPU 温度；无法可靠取得时显示热状态或“不可用”。
- GPU 占用率，整数百分比。
- GPU 温度；无法取得时显示“系统限制”或“不可用”。

布局：

- 固定支持 Top、Bottom、Left、Right 四个位置。
- HUD 建议宽 130 px、高 82 px；内部数据行宽约 112 px。
- 上方必须完整避开头部；下方必须避开悬浮光；左右对称并对齐头胸区域。
- 玻璃背景透明度 0–0.75，0 表示完全无背景和边框。
- 整体内容透明度 0.25–1.0。
- 字体：圆体、系统、等宽；数字使用等宽数字。
- 文字颜色：白、蓝、黑。
- 刷新间隔：2、5、10 秒，默认 5 秒。
- 关闭性能卡片后必须立即停止采样。

Windows 数据实现建议：

- CPU：`GetSystemTimes` 前后采样差值，限制到 0–100%。
- GPU：使用 PDH `GPU Engine(*)\\Utilization Percentage`，按物理适配器聚合；处理多 GPU 和重复引擎计数。
- GPU 设备信息：DXGI。
- 温度：Windows 没有统一可靠的普通应用 API。可选集成 LibreHardwareMonitor，并明确权限与许可证；读取失败必须显示不可用，不得猜测。
- `MSAcpi_ThermalZoneTemperature` 不能作为通用 CPU 温度来源。
- 采样必须在后台线程，UI 更新回到 Dispatcher；禁止每帧查询硬件。

## 11. 提醒系统

支持两种计划：

- 每日固定时间，24 小时制。
- 间隔重复：15、30、45、60、90、120 分钟。

提醒字段：`id`、`title`、`schedule`、`hour`、`minute`、`intervalMinutes`、`isEnabled`。

快捷内容：喝水、站起来活动、查看任务和待办、休息眼睛。

Windows 建议：

- 使用 Windows App SDK App Notifications/Toast。
- 应用常驻托盘时由单一 Scheduler 管理计时器；系统睡眠恢复后重新计算下一次触发时间，避免集中补发。
- 编辑提醒后整体重建调度，确保删除和停用不会遗留通知。
- 首次使用明确请求通知权限，并在拒绝后显示设置入口。

## 12. 设置清单与默认值

- 伙伴尺寸：140–340，步进 10，默认 220。
- 伙伴透明度：0.55–1.0，默认 1.0。
- 动作速度：0.4–1.0，步进 0.05，默认 0.8。
- 始终置顶：默认开启。
- 登录启动：默认关闭。
- 底部光亮度：0.1–1.0，步进 0.05，默认 0.72。
- 防护罩：默认关闭；三种风格。
- 情绪：默认 Calm；自动切换默认开启；默认 30 分钟。
- 性能卡片：默认关闭；默认 Right；默认 5 秒刷新。
- CPU/GPU 四项显示开关：默认开启。
- 卡片背景：默认 0.28。
- 卡片内容透明度：默认 1.0。
- 字体：默认 Rounded。
- 文字颜色：默认 White。
- 所有设置和提醒只保存在本机。

## 13. 托盘菜单

Windows 系统托盘使用 `assets/icons/eva-tray-template.svg` 作为母版，生成浅色和深色 ICO/PNG。

菜单项：

1. 显示/隐藏伊娃。
2. 动作子菜单：待机、巡航、开心、玩耍、休眠。
3. 设置。
4. 退出。

托盘图标只显示伊娃头部，不使用蓝色应用图标；需根据系统主题选择黑/白版本。

## 15. 持久化和迁移

- 推荐 `%LOCALAPPDATA%/EvaDesktopPet/settings.json` 与 `reminders.json`。
- 文件写入使用临时文件 + 原子替换，防止崩溃损坏。
- JSON 必须带 `schemaVersion`。
- 新字段必须有默认值；未知枚举回退到安全默认项。
- 旧版本提醒缺少 `schedule` 时迁移为 Daily。
- 不保存硬件采样历史，不上传遥测，除非未来取得用户明确同意。

## 16. 性能标准

发布版目标预算：

- 待机 UI 刷新 20 FPS；巡航、开心、玩耍和直接拖动最高 30 FPS。窗口跟手可由系统指针事件即时更新，不依赖动画帧率。
- 典型现代 Windows 设备空闲 CPU 目标 < 0.5%，动作状态平均 < 3%。
- 空闲 GPU 目标 < 1%，不允许持续高频硬件查询。
- Release 工作集目标 < 150 MB，硬上限 200 MB。
- 冷启动到角色可见目标 < 2 秒。
- 8 小时运行工作集增长不得超过 5%，句柄数不得持续增长。
- 关闭监控、防护罩或提示后必须停止对应计时器和渲染任务。
- 图片只解码一次并缓存；不要每帧创建 Bitmap、Brush、Geometry 或 DispatcherTimer。

## 17. 商用品质标准

- 使用 MSIX 打包并签名；发布 x64 与 arm64。
- 开启 Per-Monitor V2 DPI；测试屏幕缩放 100/125/150/200%。
- 支持 Windows 浅色、深色和高对比度；托盘图标必须可见。
- UI 文案与功能必须支持键盘操作和屏幕阅读器标签。
- 崩溃时不留下僵尸托盘图标、计时器或通知任务。
- 单实例运行；重复启动时显示现有宠物或设置窗口。
- 不要求管理员权限作为基础功能前提。
- 硬件温度扩展必须可选、可解释并遵守第三方许可证。
- 商业发布前单独进行名称、角色外观和第三方库的商标/版权审查；不要使用电影厂商标识、官方剧照或宣称官方授权。

## 18. 测试与验收清单

### 状态与视觉

- [ ] 五种动作均保持同一角色骨架。
- [ ] 巡航横向移动幅度明显大于待机。
- [ ] 五种动作眼睛与主题一致。
- [ ] 胸部始终只有一个圆形核心且严格居中。
- [ ] 休眠图标清楚、不遮挡角色。
- [ ] 玩耍火箭保持三色规范，轨迹连续。
- [ ] 状态切换无闪烁、瞬移、尺寸跳变或旧图残留。

### 交互

- [ ] 点击随机进入除当前状态外的一种状态。
- [ ] 普通状态和火箭状态都能从可见区域直接拖动。
- [ ] 拖动窗口 1:1 跟随鼠标，无追赶、卡顿或抖动。
- [ ] 尾迹、尾气、影子和火箭朝向跟随拖动方向。
- [ ] 右键菜单、托盘菜单和设置窗口不相互抢夺拖动事件。
- [ ] 多显示器、负坐标屏幕和不同 DPI 间拖动正常。

### 功能

- [ ] 性能卡片四向位置均不遮挡角色。
- [ ] 背景透明度 0 时完全无玻璃背景和边框。
- [ ] CPU/GPU 不可用时显示清晰降级文案。
